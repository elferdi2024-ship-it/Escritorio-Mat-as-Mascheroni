## 🎯 FASE 1 — Deploy de DEMO (15 minutos)

> **Objetivo:** Tener una URL pública funcional para mostrar al cliente, SIN dominio propio, SIN costos, SIN configuración avanzada.

### 1.1 Script automatizado de setup

Creá un archivo `scripts/demo-setup.sh` en tu repo:

```bash
#!/bin/bash
# scripts/demo-setup.sh
# Crea una demo completa en 5 minutos

set -e
echo "🚜 Setup de Remate Virtual Agrícola - Modo DEMO"
echo "================================================"

# 1. Crear proyecto Next.js si no existe
if [ ! -d "remate-demo" ]; then
  echo "📦 Creando proyecto Next.js..."
  npx create-next-app@14 remate-demo --ts --tailwind --app --no-src-dir --eslint
  cd remate-demo
else
  cd remate-demo
  echo "📦 Proyecto ya existe, saltando..."
fi

# 2. Instalar dependencias
echo "📦 Instalando dependencias..."
npm i @supabase/supabase-js @supabase/ssr framer-motion lucide-react zod \
      clsx tailwind-merge class-variance-authority @react-pdf/renderer
npm i -D vitest

# 3. Crear estructura de carpetas
echo "📁 Creando estructura..."
mkdir -p components/{auction,ui,layout,admin,analytics,search,pwa}
mkdir -p lib/{supabase,auction,notifications,sounds}
mkdir -p app/{lote,admin,reglamento,ganadores,api}
mkdir -p app/lote/\[id\]
mkdir -p app/admin/{dashboard,lotes,analytics,login}
mkdir -p app/admin/lotes/{nuevo,\[id\]/editar}
mkdir -p app/api/{cron,webhooks,analytics}
mkdir -p supabase
mkdir -p public/icons
mkdir -p types
mkdir -p __tests__

echo ""
echo "✅ Estructura creada. Ahora:"
echo "   1. Copiá todos los archivos del kit en sus rutas"
echo "   2. Creá un proyecto en https://supabase.com (región São Paulo)"
echo "   3. Ejecutá supabase/setup.sql en el SQL Editor"
echo "   4. Habilitá Realtime para 'lots' y 'bids'"
echo "   5. Copiá las keys a .env.local"
echo "   6. Deploy a Vercel: 'vercel --prod'"
echo ""
echo "🎯 Tiempo estimado: 15 minutos hasta tener URL pública"
```

Dale permisos y ejecutalo:
```bash
chmod +x scripts/demo-setup.sh
./scripts/demo-setup.sh
```

### 1.2 Deploy ultra-rápido a Vercel (sin CLI)

Si no querés instalar Vercel CLI:

1. Subí tu repo a GitHub (puede ser **privado**, Vercel lo soporta)
2. Andá a https://vercel.com/new
3. Click en **"Import Git Repository"** → elegí tu repo
4. Framework: **Next.js** (autodetectado)
5. Variables de entorno (las cargás en la UI de Vercel):

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...
ADMIN_USER=demo
ADMIN_PASS=demo2026
ADMIN_SECRET=string_random_largo_para_firmar_cookies
CRON_SECRET=otro_string_random
NEXT_PUBLIC_SITE_URL=https://tu-proyecto.vercel.app
NEXT_PUBLIC_WHATSAPP_NUMBER=59896125030
```

6. Click **Deploy** → en ~2 minutos tenés URL tipo `remate-agro-demo.vercel.app`

### 1.3 Generar URL de demo "pro"

Vercel te da URLs tipo `remate-agro-xxx.vercel.app`. Para tener algo más pro **sin dominio propio**:

**Opción A — Subdominio personalizado de Vercel (gratis)**
- Vercel → Settings → Domains → Add
- Poné algo como `demo-remates-agricolas.vercel.app` (si está libre)

**Opción B — Preview URL con nombre del cliente**
Cada vez que hagas un deploy de una rama (`git push origin cliente-juan`), Vercel genera una URL única:
```
remate-agro-git-cliente-juan-tu-user.vercel.app
```

**Opción C — Usar un dominio `.vercel.app` genérico**
Comprá una vez un dominio tipo `remates-agro.app` y creá subdominios para cada cliente:
```
juan.remates-agro.app
pedro.remates-agro.app
demo.remates-agro.app
```

> 💡 **Recomendación:** Opción C. Un dominio `.app` cuesta ~US$ 15/año y te da branding profesional sin que el cliente necesite comprar nada aún.

```typescript
    domain: 'demo.remate-agro.app',
  },
} as const

export type BrandKey = keyof typeof BRANDS

// Detectar brand según dominio o variable de entorno
export function getBrand(): typeof BRANDS[BrandKey] {
  // 1. Override por env (para demos)
  const envBrand = process.env.NEXT_PUBLIC_BRAND as BrandKey | undefined
  if (envBrand && BRANDS[envBrand]) return BRANDS[envBrand]

  // 2. Detección por hostname (server-side)
  if (typeof window !== 'undefined') {
    const host = window.location.hostname
    for (const [key, brand] of Object.entries(BRANDS)) {
      if (host.includes(brand.domain)) return brand
    }
  }

  return BRANDS.demo
}
```

### 4.4 Deploy multi-cliente desde UN repo

**Estrategia:** un solo repo, múltiples proyectos en Vercel, uno por cliente.

```bash
# Para cada cliente nuevo:
```

## 🛟 FASE 7 — Soporte post-venta

### 7.1 Sistema de tickets simple (gratis)

No necesitás Zendesk. Usá:

**Opción A: Notion + formulario (la más rápida)**
1. Creás un Notion database "Tickets"
2. Formulario con Tally.so (gratis) que escribe en Notion
3. Cliente carga ticket → vos respondés en Notion → le llega email

**Opción B: GitHub Issues (si el cliente es técnico)**
1. Repo privado con el cliente como collaborator
2. "New issue" = ticket
3. Labels: `bug`, `feature`, `question`, `urgent`

**Opción C: WhatsApp Business (la más usada en Latam)**
1. Grupo de WhatsApp con el cliente
2. Etiquetas de WhatsApp Business: "pendiente", "en progreso", "resuelto"
3. Una vez por semana, pasás los "resueltos" a un Excel

### 7.2 Monitoreo (sin pagar)

## 🚨 Errores comunes al vender este tipo de proyecto

| Error | Cómo evitarlo |
|---|---|
| Vender "código" en vez de "solución" | Hablá de remates exitosos, no de React |
| No cobrar setup | Siempre cobrá algo inicial, filtra clientes no-serios |
| Dar garantía de por vida | Limitá a 30-90 días, luego maintenance pago |
| Prometer features que no tenés | Mostrá SOLO lo que está funcionando |
| No tener contrato | Siempre contrato firmado, aunque sea entre amigos |
| Dar el código fuente en SaaS | Nunca. El código es tuyo. |
| No cobrar por cambios | Todo cambio post-entrega = cotización nueva |
| Soporte 24/7 gratis | Horario limitado, urgencias = extra |
